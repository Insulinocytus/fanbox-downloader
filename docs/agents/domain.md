# 领域文档

工程技能探索代码库时，应按以下规则读取领域文档。

## 探索前读取

- 仓库根目录的 `CONTEXT.md`；或者
- 如果根目录存在 `CONTEXT-MAP.md`，先读取它，再读取其中指向且与当前任务相关的各个 `CONTEXT.md`。
- 阅读 `docs/adr/` 中与当前工作区域有关的 ADR。多上下文仓库还应检查 `src/<context>/docs/adr/`。

如果这些文件不存在，静默继续。不要报告缺失，也不要提前建议创建。`/domain-modeling` 技能会在术语或决策真正明确时按需创建它们。

## 文件结构

本仓库使用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 使用术语表中的词汇

输出中命名领域概念时，应使用 `CONTEXT.md` 定义的术语，不要改用术语表明确排除的同义词。

如果需要的概念尚未记录，先判断是否在创造项目并未使用的新词；若确实存在领域模型缺口，则记录下来，交由 `/domain-modeling` 处理。

## 标记与 ADR 的冲突

如果输出与现有 ADR 冲突，必须明确指出，而不是静默覆盖：

> 与 ADR-0007 冲突，但值得重新讨论，因为……
