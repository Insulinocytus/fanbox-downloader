## Why

每轮下载都会请求作者的全部帖子分页，即使绝大多数帖子已经下载，随着历史帖子增长会持续增加耗时和 Cloudflare 请求压力。单一位置游标又会受到 FANBOX 置顶和取消置顶影响，因此需要以帖子 ID 为基础的持久化处理记录。

## What Changes

- 在持久化下载目录中保存按作者分组的 JSON 帖子处理清单，以帖子 ID 而不是列表位置判断帖子是否完成。
- 仅在帖子全部文件成功处理或确认没有文件后记录完成；失败或中断的帖子保持未完成并在后续运行重试。
- 普通运行使用处理清单过滤帖子，并在连续已知页面形成安全重叠后结束快速扫描；仅在首次运行或状态不可用时执行完整扫描以建立或重建清单。
- 使用原子文件替换保存状态，使容器中断不会留下部分写入的 JSON。
- 保持下载目录为唯一需要挂载的持久化目录，不增加数据库或新依赖。
- 更新文档和测试，说明状态恢复、初始化重建及不完整下载重试行为。

## Capabilities

### New Capabilities

- `incremental-post-scanning`: 定义基于持久化帖子 ID 清单的增量扫描、完成记录、失败恢复和状态重建行为。

## Impact

- 主要影响 `fanbox_dl.py` 的帖子枚举、完成判断和运行状态持久化逻辑。
- 测试将覆盖置顶顺序变化、状态文件恢复、失败重试、首次完整扫描和后续快速扫描。
- README 将说明状态文件位于下载目录中，以及删除或损坏状态后的完整重建行为。
- 不新增第三方依赖；状态继续随现有 `/data/downloads` volume 持久化。
